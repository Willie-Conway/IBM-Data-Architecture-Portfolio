## Introduction

**FashionMart**, a mature brick-and-mortar chain, has bought **TrendyThreads**, a technology-sophisticated online clothing retailer. The primary goal of this merger is to integrate TrendyThreads' state-of-the-art digital platform with FashionMart's robust physical infrastructure to form a single, complementary enterprise architecture. This combined system will drive an **omnichannel retail experience**, blending TrendyThreads' digital capabilities with FashionMart's in-store operations.

---

## Project Phases Overview

The acquisition will be implemented by a phased migration, with the project broken down into the following major phases:

| Phase             | Description                                                          |
| ----------------- | -------------------------------------------------------------------- |
| **Phase 1** | Assess the data architecture of FashionMart & TrendyThreads          |
| **Phase 2** | Develop the data architecture of the merged entity FutureMart        |
| **Phase 3** | Convert the data to the new data architecture                        |
| **Phase 4** | Merge the data systems for smooth data flow within the merged entity |
| **Phase 5** | Prepare the data governance plan for the merged entity               |

**The project task in this module addresses Phase 1 of the project.**

---

During Phase 1, your responsibility is to thoroughly assess the existing data architectures of FashionMart and TrendyThreads. This assessment is intended to determine gaps, inefficiencies, and improvement areas before the integration process.

## Tasks

### Part 1: Create the Enterprise Data Architecture (EDA) Blueprint for FashionMart

In this part, you'll design a comprehensive EDA blueprint for FashionMart, including critical architectural layers, tools, and processes to ensure secure and efficient data flow across the organization.

**Include the following key architectural layers in the EDA blueprint:**

| Layer                     | Description                                                                                          |
| ------------------------- | ---------------------------------------------------------------------------------------------------- |
| **Data Sources**    | Retail store data, online web-store data, customer data, supply chain data, marketing campaigns data |
| **Data Ingestion**  | Collection of raw data from various sources                                                          |
| **Data Storage**    | CRM, showroom sales database, data warehouse1, website sales database, data warehouse2               |
| **Data Processing** | Data transformation, ETL processes                                                                   |
| **Analytics**       | Business Intelligence tools, dashboards, KPI tracking                                                |
| **Security**        | Access control, RBAC, data encryption                                                                |

### Part 3: Evaluate FashionMart's Data Architecture

In this part, you'll assess FashionMart's current data architecture by reviewing its key architectural components and documenting strengths and improvement areas across **any 3** of the following:

| Evaluation Criteria                               | Description                                                         |
| ------------------------------------------------- | ------------------------------------------------------------------- |
| **Data silos**                              | Are there isolated data systems that don't communicate effectively? |
| **Legacy systems**                          | Are there outdated systems that need modernization?                 |
| **Scalable data architecture**              | Can the architecture handle growth in data volume and users?        |
| **Data integration capabilities**           | How well do different systems integrate and share data?             |
| **Robust data governance**                  | Are there clear policies for data quality, ownership, and usage?    |
| **Performance bottlenecks**                 | Where are the slowdowns in data processing?                         |
| **High availability and disaster recovery** | Are there plans for system failures and data recovery?              |
| **Analytics and BI tools**                  | How mature are the reporting and analytics capabilities?            |
| **Data security measures**                  | How well is sensitive data protected?                               |

---
